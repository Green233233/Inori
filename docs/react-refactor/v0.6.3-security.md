# v0.6.3 安全排查

## 数据与权限
- **端到端加密不变**：ECDH P-256 → HKDF-SHA256(salt=`qi/pair/<pairId>`) → AES-256-GCM，全部在 Kotlin（`QiCrypto`/`QiSecureStore`/`QiApiClient`）；JS 只见密文。券卡密由服务端 Ed25519 签名，是唯一已文档化的例外。
- **新增的两条原生命令都走密文**：`app.limit`（主人下发名单）与 `guard.lock`（主人要求锁屏）经 `PairRelayCrypto.open` 解密、执行后再 `seal` 回执；服务端只看到 `kind` 与密文，看不到包名或锁屏内容。
- **应用限制的权限边界**
  - 名单来自主人，但**受控端始终能自行关闭**：`PermissionCenter` 的「应用限制」Switch 直接写本机 `qi.limits.xml`（`enabled=false`）并通过 relay 回传主人端，主人端只读展示，**不能远程重新打开**。
  - 拦截只做「遮挡 + 一句说明 + 我知道了」，不读取被禁应用内容、不注入、不阻止返回键（浮层 `FLAG_NOT_FOCUSABLE`，返回键仍给下层）。
  - 应用列表解析只用于显示名字，`resolveLabel` 单包查询；**没有** `QUERY_ALL_PACKAGES`，也没有全量 `getInstalledPackages`。
  - 审计 `app.limit.block` 写本机 `files/qi/audit.jsonl`（同包 60s 去抖），不上传内容。
- **设备管理器（P5.5 结论）**
  - 只申请 `force-lock` 一项策略（`device_admin.xml`），**不具备** wipe / 密码策略 / 安装卸载 / 保活等能力；`lockNow()` 只在主人点「远程锁屏」时调用，并留 `admin.remoteLock` 审计。
  - 撤销路径改为应用自己调 `DevicePolicyManager.removeActiveAdmin()`（Android 15 已没有 REMOVE_DEVICE_ADMIN 系统页），符合「受控端永远可自行解除控制」。
- **通知权限**：Android 13+ 必须运行时申请 `POST_NOTIFICATIONS`，否则通知被静默丢弃（这就是主人端之前收不到「小狗刚刚查看了你的位置」的原因）。已在 `MainActivity.onCreate` 主动请求；这是可见的通知，正文只有「小狗刚刚查看了你的位置」这类事实描述，不含位置内容本身。
- **公网部署**
  - `release` 必须 HTTPS：`network_security_config.xml` 为 `cleartextTrafficPermitted="false"`，release 走 `https://124-221-102-236.sslip.io:8443`。
  - 证书是 10 年自签（未备案域名拿不到公共证书：80 被备案拦截页占用、443 按 SNI reset），因此客户端启用**证书指纹 pin**（`DEFAULT_SERVER_PIN`，非空时跳过主机名校验，pin 不匹配直接拒绝连接）。
  - 服务端 systemd：`User=inorinal`、`ProtectSystem=strict`、仅监听 `127.0.0.1:8095`，由 Caddy 反代到 8443；数据在 `/var/lib/inorinal`。

## 已知限制（写入产品说明）
- **会自己隐藏非系统浮层的应用拦不住**：系统设置等敏感页调用 `setHideOverlayWindows(true)` 后，我们的 `TYPE_APPLICATION_OVERLAY` 窗口 `mPolicyVisibility=false`、`isVisible=false`。这类应用需要 `AccessibilityService` 才能拦，本版明确不引入（避免「读取输入」的能力），因此列为已知限制。
- relay 的明文 `kind` 暴露「有一条指令」这一元事实（不含内容）。
- debug 包允许明文 HTTP（`usesCleartextTraffic` 仅 debug）。

## 残留风险
- 应用限制依赖「1.5s 轮询 + 浮层」，被禁应用在极短时间内仍可能露出一帧；对高敏感场景（银行类）不构成可靠管控，UI 与文档都已声明是「情侣角色扮演里的约定」，不是家长控制级方案。
- 自签证书依赖 pin；若服务端换证书必须同步发新版客户端，否则连接失败（这是有意的 fail-closed）。
