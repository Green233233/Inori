## 关键回归细节

### 启动与安装
- 双端 `install -r` 后**必须** `adb shell cmd package compile -m speed -f com.green.inori`，否则 debug APK 未 AOT，`am start -W` 会 10s+ 甚至 `Status: timeout`（v0.6.2 已记录同一现象）。
- AOT 之后本轮实测：主人端 `WaitTime: 744ms / 2069ms`，小狗端 `WaitTime: 1255ms ~ 408ms`。
- 启动组件是 `com.green.inori/com.inorinal.MainActivity`（命名空间 `com.inorinal`，写 `.MainActivity` 会 `Error type 3`）。

### ⑥ 应用限制的三处修复（本轮真正的工作量）
1. **下发链路必须走原生**。原实现只在 `react-native/src/sync/appLimit.ts` 的 `handleAppLimit` 里处理 `app.limit`，而 relay 循环只在 JS 前台跑；小狗端 app 退到后台后规则永远到不了。现在 `QiLinkService.handlePage` 里 `kind == "app.limit"` 走 `applyAppLimit()`：`PairRelayCrypto.open` 解密 → `AppLimitWatcher.applyRules` → `AppLimitWatcher.start`（幂等）→ 仅在成功后 `acknowledge`。JS 路径保留作前台兜底，两边幂等。
2. **浮层被系统策略隐藏**。第一版用 `com.android.settings` 复测时 `dumpsys window` 里窗口已存在（`ty=APPLICATION_OVERLAY`、`mHasSurface=true`、`mViewVisibility=0x0`），但 `mForceHideNonSystemOverlayWindow=true` → `mPolicyVisibility=false`、`isVisible=false`。原因是系统设置等敏感页会调 `setHideOverlayWindows(true)` 强制隐藏非系统浮层。换 `com.android.chrome` 复测即正常显示。**这是已知限制**（详见 `v0.6.3-security.md`），不是代码缺陷。
3. **判断浮层是否真的显示**要用 `dumpsys window windows` 里该 `Window{… com.green.inori}` 的 `isVisible`；窗口 id 每次重建都会变，别复用旧 id 查询（本轮曾因此误判「点我知道了没反应」，实际是查到旧窗口）。

### P5.5 设备管理器的两个坑
- 组件名必须是 `com.green.inori/com.inorinal.qi.QiDeviceAdminReceiver`。manifest 没写 `package=`，命名空间由 `namespace com.inorinal` 决定，所以 `.qi.QiDeviceAdminReceiver` 这种相对名会解析成不存在的 `com.green.inori.qi.…`，`am start -a android.app.action.ADD_DEVICE_ADMIN` 会「什么都没发生」。
- Android 15 已移除 `android.app.action.REMOVE_DEVICE_ADMIN` / `DEVICE_ADMIN_SETTINGS`（`cmd package resolve-activity` 三个候选全 `No activity found`），`dpm remove-active-admin` 对非 testOnly admin 抛 `SecurityException`。撤销只能由应用自己调 `DevicePolicyManager.removeActiveAdmin()`——`PermissionCenterModule.revoke()` 已按此改写。
- 模拟器没有安全锁屏，`lockNow()` 只让屏幕熄灭，唤醒后 `isKeyguardShowing=false`；所以「锁屏界面」无法在模拟器截图，证据取 `audit.jsonl` 的 `admin.remoteLock` + `mAwake=false`。真机设了密码才会看到锁屏。

### ① TA 只读的一次反复
本轮前半段曾看到「有底部编辑工具条 + 正文是 base64 乱码」，据此误判只读失效；复查发现点的是**自己的**「2026年11月18日 星期三」条目（同日期两条并存，TA 那条标题是 `test`）。改点 TA 卡后：标题 `test` + 「只读」徽标 + 无工具条，判定通过。
同一条自建条目在**编辑态**打开时仍会触发 WebView 渲染进程崩溃（条目内联了两张整幅 base64 照片：`partner.json` 里 204575 / 110275 字符），`onRenderProcessGone` 自愈后降级纯文本——本版已修「回退泄漏 base64」（`EditorScreen.toPlainPreview` 先剥离 `<img>` 与 `data:…;base64,…`），**但该项尚未真机复验**，见「未完成项」。

### 其他 UI 修复
- 长包名换行：`TrailTimeline.tsx` 事件标题改 `numberOfLines={1}` + `ellipsizeMode="tail"`；`UsageStatsScreen.tsx` 应用名原本已是单行，本轮真机确认 `com.google.android.apps.nexuslauncher` 单行省略。
- 设备管控中心 tile 现为 6 个：查看屏幕 / 使用时长 / 应用限制 / 全屏消息 / **远程锁屏**（新）/ 守护状态；定位与通知两个 tile 已按 v0.6.2 需求移除，定位入口移到「小狗轨迹」。
