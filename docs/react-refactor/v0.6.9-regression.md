## 本轮改动

1. **应用限制读小狗端列表**（⑤）：新增原生 `QiAppCatalog.launchable()`（`ACTION_MAIN` + `CATEGORY_LAUNCHER`，包名去重、`Collator` 排序，不带图标，不申请 `QUERY_ALL_PACKAGES`），`QiLinkService` 登记 `apps.list` 为原生命令；主人端 `AppLimitScreen` 改走 `runCommand('apps.list')`，不再读主人本机列表。
2. **锁屏即回**（④）：`QiLinkService.ensureUnlocked(kind)` 在 `executeReadOnlyCommand` 入口检查 `KeyguardManager.isKeyguardLocked`（`guard.lock` 例外），锁屏时立刻回 `小狗端已锁屏`。
3. **长轮询退避**（⑥）：`QiProvider` relay 轮询失败按 6→12→30→60s 指数退避（优先 `ApiError.retryAfter`），401 直接 `clearSession()` 回登录页，成功复位。
4. **7 天用时长改系统聚合**（Android 11 性能）：`UsageStatsModule.rangeStatsBlock()` 由 `queryEvents` 扫 7 天事件改为 `queryUsageStats(INTERVAL_DAILY)`，避免低配机越过 20s 看门狗。

## 定位回包被中断（本轮新发现并修复）

- 链路：`location.get` 原生执行时先用 `Geocoder` 反查地址，失败后回落到 Nominatim（`LocationModule` 内置 HTTP）。
- 故障：两个 HTTP 超时都是 6s，模拟器/弱网下 Geocoder 超时 + Nominatim 连接与读取各 6s，累计逼近 `QiLinkService.COMMAND_TIMEOUT_MS = 20_000L`；看门狗 `self.interrupt()` 后，`runNativeCommand` 末尾那条 `POST /api/v1/relay/send`（15s）带着中断位立刻抛 `InterruptedIOException`，回包丢失且不 ack —— 主人端永远停在「正在取…」。
- 修复：
  1. `LocationModule.kt` 的 `HTTP_CONNECT_TIMEOUT_MS` / `HTTP_READ_TIMEOUT_MS` 由 `6_000` 降到 `3_000`，最坏路径从 12s 降到 6s；
  2. `QiLinkService.kt` 在封包后、发回包前显式 `Thread.interrupted()` 清中断位；
  3. 新增 `sendReplyWithRetry(body, token)`：写中继最多两遍（每次 12s 超时，首次失败 `sleep(800)` 后重试，幂等），避免一次网络抖动就把结果丢掉。
- 复验结果：装加固包后点「取一次位置」→ relay `(568,'command.send',139,'06:07:32','06:07:49')` + 两条 `command.reply(574 B)`（06:07:38 / 06:07:49），06:07:49 完成 ack；主人端轨迹新增一条位置条目 `39.23726, -123.15003 · 06:07`，头部从「0 次移动」变为「1 次移动 · 65 分钟屏幕时间」。日志里 `geocoder_failed` / `nominatim_failed` 仍出现（模拟器无网），但**不再丢回包**——正是本次加固要保证的降级行为。
- 同类风险：任何会先做网络反查再回包的原生命令（当前只有定位）都可能触发，故把「清中断位 + 回包重试」放在统一的 `runNativeCommand` 出口，而非只修定位。
