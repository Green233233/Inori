## 已修复：③「屏幕使用时长」取不到数据

现象：主人端「屏幕使用时长」页固定 `小于 1 分钟`，并在 20～40 秒后显示「对方没有响应哦，可能离线或未授权呀」。

**根因（读码 + 生产库取证确认）**：页面 `load()` 发的是三条命令 `usage.day`（当天）、`usage.day`（前一天）、`usage.range`（7 天），而原生指令白名单里只有 `usage.stats`：
- Kotlin `react-native/android/app/src/main/java/com/inorinal/qi/QiLinkService.kt` 的 `NATIVE_COMMAND_KINDS` 原本只有 `location.get` / `usage.stats` / `permissions.snapshot` / `guard.lock` / `overlay.show` / `notifications.drain`；
- JS `react-native/src/features/qi/QiProvider.tsx` 只有 `location.get` / `usage.stats` / `permissions.snapshot`。

于是这三个 kind 落到小狗端的 JS 分支，小狗端没开着祈时无人消费 relay，主人端只能等 40 秒超时。生产库 `relay` 也印证：`permissions.snapshot` 这类原生指令 1 秒内就有 `command.reply`，而三条并发命令里总有一条始终没有回包（`seq 138/139/140` → 只有 `141/142`），`Promise.all` 因此整页失败——这正是「经常连不上」而非「完全连不上」的原因。

**修复（提交 `2810453`）**：
- `UsageStatsModule.kt` 增加 `internal object QiUsageReport`（`attach/detach` + `day/range/sessions`），复用模块内部既有的 `dayStatsBlock` / `rangeStatsBlock` / `sessionsBlock`，不复制事件流切分逻辑，保证与 `UsageDaySummary` / `UsageRangeStats` / `UsageSessions` 形状一致。
- `QiLinkService.kt` 新增 `usage.day` / `usage.range` / `usage.sessions` 三条原生分支并登记进 `NATIVE_COMMAND_KINDS`；`usage.day` 缺省取本地当天零点，`usage.sessions` 缺省最近 24h。
- `QiProvider.tsx` 同步这三个 kind 到 JS 白名单，避免双端重复回包。
- `UsageStatsScreen.tsx` 的 `load()` 改成 `Promise.allSettled`：只要当天那条成功就先渲染，7 天汇总慢或失败不再清空整页。

验证：小狗端装上新包后，11/20 页面显示「1 小时 57 分钟 · 比前一天减少 35 分钟」+ 每小时分布 + 分类占比 + Top 应用列表。

## 取证限制

- release 包不可 debug：`run-as com.green.inori` 报 `package not debuggable`，`adb root` 报 `adbd cannot run as root in production builds`。需要读私有目录时的办法：装 **debug** 包（`react-native/android/app/build.gradle:64` 的 `debuggableVariants = []`、无 `applicationIdSuffix`，与 release 同 `applicationId`，`install -r` 原地覆盖且数据保留），`run-as` 读完再装回 release。
- 生产库取证只 SELECT 必要列（`seq/kind/from_device/to_device/substr(created_at,12,8)`），避免把 `ciphertext` 打进日志。
- ⑤ 的下载地址仍由 `server/app/update.py` 的 `DOWNLOAD_URL` 提供，当前是 GitHub Releases 占位；要换成网盘直链只需改这一个字段（客户端读服务端下发的 `downloadUrl`）。
