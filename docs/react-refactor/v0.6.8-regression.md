## 未闭环：③「屏幕使用时长」取不到数据

现象：主人端「屏幕使用时长」页固定 `小于 1 分钟`，并在 20～40 秒后显示「对方没有响应哦，可能离线或未授权呀」；换日期（11/19、11/20）与「显示今天」都一样。

**根因（读码确认，非猜测）**：`react-native/src/features/control/UsageStatsScreen.tsx:80-84` 的 `load()` 发的是三条命令

```ts
runCommand('usage.day', {dayStartMs})
runCommand('usage.day', {dayStartMs: dayStartMs - DAY_MS})
runCommand('usage.range', {days: 7})
```

而原生指令白名单里只有 `usage.stats`：

- Kotlin：`react-native/android/app/src/main/java/com/inorinal/qi/QiLinkService.kt` 的 `NATIVE_COMMAND_KINDS` = `location.get` / `usage.stats` / `permissions.snapshot` / `guard.lock` / `overlay.show` / `notifications.drain`
- JS：`react-native/src/features/qi/QiProvider.tsx:94-100` = `location.get` / `usage.stats` / `permissions.snapshot`

所以 `usage.day` / `usage.range` 命中的是小狗端的 **JS** 执行分支（`react-native/src/sync/commands.ts` 的 `runLocalCommand`），小狗端不在前台时没有 JS 消费 relay 消息，主人端只能等 40 秒超时。生产库 `relay` 表也印证：同一时段 `permissions.snapshot` 这类原生指令 1 秒内回包，而这一页始终没有对应 `command.reply`。

旁证：小狗端 `GET_USAGE_STATS` 为 `allow`、无障碍服务已启用，权限不是原因；「查看授权状态」「小狗轨迹」都能出数据，说明 relay、加解密、配对都没问题。

**修复方案（留给 v0.6.9）**：把 `usage.day` / `usage.range`（以及轨迹页面用的 `usage.sessions`）登记进原生白名单，并在 `QiLinkService` 用 `QiUsageAggregator` 现有能力回包：

- 需要把 `react-native/android/app/src/main/java/com/inorinal/qi/UsageStatsModule.kt` 里的 `dayStatsBlock` / `rangeStatsBlock` / `collectDays` / `buildDayMap`（当前均为 `private`）提成可复用的 `internal`（或搬进 `QiUsageAggregator`），保证原生回包形状与 `UsageDaySummary`（`dayStartMs/totalMinutes/perHour[24]/byCategory/apps`）和 `UsageRangeStats`（`totalMinutes/days[]`）完全一致。
- 同时把 JS 侧 `NATIVE_COMMAND_KINDS` 补齐，让 `QiProvider` 在原生可用时跳过本地执行，避免双端重复回包。
- 注意不要在一次回包里顺带算 7 天事件流（`eventsBlock(7)`），那是 20 秒看门狗被打断的来源之一。

> 本轮曾试做「只把 `usage.stats` 的 `eventsBlock(7)` 砍掉」，实测小狗端确实 1 秒回包，但页面用的是 `usage.day/range`，所以对现象无影响，改动已回退，源码与 `v0.6.8` tag 一致。

## 取证限制

- release 包不可 debug：`run-as com.green.inori` 报 `package not debuggable`，`adb root` 报 `adbd cannot run as root in production builds`；小狗端 `logcat` 对 `QiLinkService` 无任何输出，只能靠服务端 relay 记录与 UI 行为反推。
- 生产库取证只 SELECT 必要列（`seq/kind/from_device/to_device/substr(created_at,12,8)`），避免把 `ciphertext` 打进日志。
