## 已知问题

1. 使用时长 Top 应用当前显示包名（已加 `<queries>` 声明，需重装后复验应用名）
2. 主人端「电量」在部分时刻显示 `—`（presence 里 battery 未上报，需把电量并入心跳）
3. 小狗端 app 长时间后台后 relay 轮询停止（设计如此），主人端会看到超时提示
4. Android 13 及以下的「常驻截屏」链路无对应模拟器镜像，仅代码审查 + 单元级验证
5. 权限列表的「无障碍服务」恒为未授权（刻意不声明 AccessibilityService）
6. Release 包默认只允许 HTTPS，本地 HTTP 联调需用 debug 包；正式自托管请用反向代理提供 TLS
7. Release 使用 debug keystore 签名（沿用 RN 模板），正式分发前需生成自己的 keystore 并更新 `signingConfigs.release`

### 日记重复副本修复（自己条目被对方推回，2026-11-18 14:35）

- 现象：主人端日记列表出现「18 11月 · 带图片的日记测试 · TA」——是**自己**写的共享日记被标成 TA。
- 根因：`react-native/src/sync/partnerStore.ts` 的 `pushOwnEntries` 遍历本地日记索引时不区分来源；对方共享过来的镜像被合并进本地列表后会再次被推回服务器，且 `authorDeviceId` 被改写成推送者，于是原作者端收到自己的「TA 副本」，且每轮同步都可能再生一条。
- 修复：取到 entry 后加守卫 `if (entry.authorDeviceId && entry.authorDeviceId !== myDeviceId) { continue; }`（只推自己写的条目）。
- 清理：删除服务器伪记录 `jra4d6235d-da9f-21ec-b9df-51e1e8a22b62`（当时 author_device=小狗端），让主人端重新推送为自有记录；并清空 `files/qi/partner.json` 让镜像重建（注意真实文件名是 **partner.json**，不是 partners.json）。
- 复验（双端均最新 debug）：服务器仅剩 5 条 journal + 1 条 legacy，`author_device` 全部与真实作者一致；主人端列表 **6 篇**（自己 5 + 小狗端 1），小狗端 **11 篇**，两端都不再出现自己条目的「TA 副本」；再次下拉刷新不会新增记录（seq 不再增长）。
