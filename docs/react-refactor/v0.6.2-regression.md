## 关键回归细节

### 启动性能（重要教训）
- 首次安装后 `am start -W` 报 `Status: timeout`，logcat 时间线为 `Start proc … → ziparchive: Unable to open base.dm → Process … failed to attach → Killing … (adj 0): start timeout`，伴随 `Verification of void com.inorinal.MainApplication.<init>() took 601ms`。
- 真因：**debug APK 未 AOT**，ART verify 把冷启动拖过 ActivityManager 超时。
- 处理：`adb shell cmd package compile -m speed -f com.green.inorinal` 后冷启从 72–113s 降到约 15s。发布版（release + R8）不受此影响。

### 日记编辑器
- 自建条目：正文、⭐ 贴纸、照片、涂鸦、底部工具条（文字/涂鸦/照片/贴纸）均正常。
- 只读链路：`EditorScreen readOnly` 关闭保存与工具条、`?view=1` + `window.setReadOnly(true)` 双保险；TA 条目真机点击多次未进入（列表滚动后坐标失效），未完成最终确认。
- 多图滚动：`editor.css` 已把滚动容器从 `#paper` 上移到 `html,body`（原实现内层滚动 + 图片异步撑高导致拖不动）。
- 已知缺陷：`[涂鸦]` 条目（只有涂鸦）打开后停在骨架 spinner，已加「淡入完成后 300ms 强制隐藏骨架」兜底，需下一次构建复验。

### 命令类交互的前提
- `command.send` 只由小狗端**前台进程**执行（`QiLinkService` 仅 ack + 通知）。relay 表核验：小狗端进程未启动时 `location.get` 只落 `command.send`，无对应 `command.reply`；启动后即成功。
- 主人端命令超时默认值由 25s 提到 40s（小狗端 25s 长轮询 + 加解密刚好越过 25s）。
