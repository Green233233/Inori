# v0.7.0 回归记录（状态暂存 + 日记云同步 + 后台 v0.2.0）

日期：2026-11-21
分支：`react`
版本：App `v0.7.0` / `versionCode 19`；服务端 `0.7.0`；管理后台 `0.2.0`

## 本次改动

- 状态类信息改为「发送端定时加密上传 → 服务器暂存 → 接收端按游标拉取」，不再要求双方同时在线。
- 新增 `staged_items` / `storage_samples`，每对暂存默认 72 小时、150 MB（可按配对单独配置），90% 进入 pressure；`dedupeKey` 只保留最新快照。
- 日记云同步扩展 `sync_records.audience`：`pair` 双方可见，`self` 仅作者设备可见；每对默认 1 GB 云配额，超限 507 `cloud_full`。
- 新增 `GET /api/v1/sync/quota`、`/api/v1/staging/{send,poll,ack,quota}`。
- 管理后台 v0.2.0：存储用量图表、账号暂存/云空间清理、配对配额、公告路由修复、登录页跟随系统深浅色。
- 直连命令保留为兜底：缓存为空、超过新鲜阈值（状态/定位 10 分钟，使用时长/轨迹/权限/应用限制 30 分钟，通知 5 分钟，头像昵称 24 小时）或暂存连续失败 ≥2 轮时使用；每 kind 冷却 60 秒。

## 安全审计（code-audit standard）与修复

- **日记记录越权改写（High）**：同一配对的另一方知道 `recordId` 后可覆盖/删除对方 journal 记录。已在 `server/app/sync.py` 的 `put_record()` 增加作者校验：`kind == 'journal'` 且已有记录作者不是当前设备时返回 403 `not_record_author`；补充回归测试。
- **暂存游标参数不一致（Medium）**：客户端用 `sinceRev`，服务端只读 `cursor`，导致游标被忽略、旧条目反复投递。已让 `/api/v1/staging/poll` 同时接受 `sinceRev`、`cursor`，并补充游标测试。
- 新增 SQL 均参数化；暂存与配额路径未发现注入、路径穿越或未授权访问。
- 管理后台新路由均在管理员会话校验之后；公告/账号存储/配额接口仅管理员可达。

## 每对绑定独立云配额与暂存门禁（后续增补）

- `pairs` 增加 `staging_ttl_hours`（默认 72）、`staging_budget_bytes`（默认 150 MB）、`staging_time_gate`、`staging_size_gate`；`staging.pair_limits()` 统一读取并钳制到 1–720 小时、1 MB–2 GB。
- 关闭时间门禁后不按时间过期（到期时间延到约 100 年），重新开启或修改时长时会把未 ack 条目的 `expires_at` 重设为当前时间 + TTL；关闭容量门禁后不再按容量淘汰，仅保留 2000 条硬上限。
- 管理后台存储弹窗可为每个配对设置云配额 GB、暂存时长小时、暂存容量 MB、时间/容量门禁开关；`PATCH /admin/api/pairs/{id}/limits` 部分更新，`GET` 读取；兼容旧 `/quota`。
- 手机端日记设置页在 App 回到前台或点「刷新」时重新拉取 `GET /api/v1/sync/quota`，云空间大小可即时刷新。
- 验证：服务端 31 项通过；`PATCH/GET /admin/api/pairs/pairv070/limits` 手工验证 quota 2 GB / TTL 24h / budget 50 MB / 时间门禁关 / 容量门禁开；Playwright 存储弹窗字段与保存无 pageerror；`admin_e2e.py` 53 项通过；`npx tsc --noEmit`、Jest 59 项通过。
